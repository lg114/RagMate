# HTTP 缓存与 CDN 笔记

本文记录 RagMate 前端静态资源与 API 响应的 HTTP 缓存策略，CDN 为
Cloudflare，源站为 Cloudflare Workers 上的 Next.js 应用。

## 强制缓存：max-age

强制缓存指响应在有效期内直接用本地缓存，不发任何请求：

```
Cache-Control: public, max-age=3600
```

`max-age=3600` 表示该响应在 3600 秒内是新鲜的，浏览器直接用缓存，
不向服务器发请求。`public` 表示响应可以被任何缓存存储，包括共享缓存
（CDN、代理）；`private` 则只允许最终用户的浏览器缓存，不允许共享
缓存存储。

静态资源（带内容哈希的文件名，如 `app-9f3c2a.js`）用
`max-age=31536000, immutable`：文件名随内容变化，内容不变则 URL 不变，
一年内强制缓存且 `immutable` 声明响应内容永不改变，浏览器连条件请求
都不发。HTML 文档不用强制缓存：`Cache-Control: no-cache`，每次使用前
必须向服务器验证，服务器返回 304 则用缓存。

## no-cache 与 no-store：容易混淆的一对

`no-cache` 不是“不缓存”：响应可以存进缓存，但**每次使用前必须先向
服务器验证**，服务器返回 304 才能用缓存，返回 200 则用新响应。
`no-store` 才是完全不存：请求与响应都不写入任何缓存，登录态、私密
数据用 `no-store`。

一句话区分：`no-cache` 是“存了也要先问”，`no-store` 是“根本不存”。

## 协商缓存：ETag 与 Last-Modified

强制缓存过期后，浏览器用协商缓存向服务器验证资源有没有变，常用两种
验证器：

**ETag**：服务器给响应生成一个内容指纹，例如 `ETag: "9f3c2a"`。
浏览器下次请求带上 `If-None-Match: "9f3c2a"`，服务器比对指纹一致
则返回 `304 Not Modified` 且**不带响应体**，浏览器用缓存；指纹不一致
则返回 200 与新响应。

**Last-Modified**：服务器给 `Last-Modified` 时间戳，浏览器下次带
`If-Modified-Since`，资源在该时间后没改过则返回 304。时间戳精度只到
秒，1 秒内多次修改分辨不出来，精度不如 ETag；两者同时存在时 ETag
优先。

协商缓存的请求仍然要发到服务器（或 CDN 节点），省的是响应体传输，
不是请求本身。304 响应没有响应体，但仍有往返延迟，强缓存命中率优先
于协商缓存。

## s-maxage：共享缓存的专属指令

```
Cache-Control: public, max-age=60, s-maxage=3600
```

`s-maxage` 只对共享缓存（CDN、代理）生效，会覆盖 `max-age`：CDN 节点
按 3600 秒缓存，浏览器按 60 秒缓存。私有缓存（浏览器）忽略
`s-maxage`。需要“CDN 长缓存、浏览器短缓存”时用它，例如 API 响应希望
CDN 挡一小时，但浏览器一分钟后重新验证。

## CDN 回源与缓存键

CDN 节点没有缓存、或缓存过期时，向源站拉取内容，称为**回源**。
回源时 CDN 带着原始请求的 Host 与路径访问源站，源站返回的
`Cache-Control` 决定 CDN 节点缓存多久。

缓存键默认是完整 URL（含查询字符串）：`/api/posts?page=2` 与
`/api/posts?page=3` 是两个不同的缓存条目。查询字符串里带随机参数
（如 `?v=随机数`）会让每次请求的缓存键都不同，缓存永远命中不了，
俗称缓存击穿式绕过，联调时先确认 URL 里没有这类参数。

`Vary: Accept-Encoding` 告诉缓存：响应内容随 `Accept-Encoding` 请求头
变化，压缩版（gzip/br）与未压缩版是**两个不同的缓存条目**，不能互相
混用。漏写 `Vary` 时，CDN 可能把 gzip 版缓存发给不支持 gzip 的客户端，
导致页面乱码。

## 缓存顺序：强制缓存 → 协商缓存

浏览器处理一次请求的顺序固定：

1. 先看强制缓存：`max-age` 未过期，直接用缓存，不发请求；
2. 强制缓存过期，看协商缓存：带 `If-None-Match` 或 `If-Modified-Since`
   发请求，304 用缓存、200 用新响应；
3. 没有任何缓存信息，直接发请求取新响应。

调试缓存问题时先看响应头里 `Cache-Control` 与 `Age`：`Age` 是响应在
共享缓存里已经存放的秒数，`Age` 接近 `max-age` 说明快过期了。

# Linux 进程与信号笔记

本文记录 RagMate 部署脚本与运维手册里用到的 Linux 进程知识，环境为
Ubuntu 22.04，内核 6.x，shell 为 bash。

## fork 与 exec：创建进程的两步

Linux 创建新进程分两步：`fork()` 复制当前进程，`exec()` 把新进程的
内存映像替换成要运行的程序。shell 里敲一条命令，就是先 `fork()` 一个
子进程，再 `exec()` 目标程序。

`fork()` 之后父子进程的内存关系是**写时复制（Copy-On-Write）**：fork
的瞬间父子共享同一批物理页，任何一方写入某个页时，内核才为写入方
复制该页。只读数据（程序代码、常量）整个生命周期都共享，fork 的代价
远低于完整复制一份内存。

`fork()` 的返回值区分父子：父进程拿到子进程的 PID（正数），子进程
拿到 0，失败返回 -1。`exec()` 成功后不返回，失败才返回 -1 并保留原
进程映像。

## 信号：SIGTERM 与 SIGKILL

信号是内核/进程间发给进程的异步通知，`kill -l` 列出全部信号名与编号：

```
 1) SIGHUP   2) SIGINT   9) SIGKILL  15) SIGTERM
```

（完整列表以 `kill -l` 输出为准，上面只摘了常用的几个。）

**SIGTERM（15）**是“请你退出”的礼貌通知：进程可以捕获它，做完清理
工作（关闭连接、刷盘、保存状态）再退出。`docker stop` 默认先发
SIGTERM，等 10 秒（`--time` 可改）后进程还没退出才发 SIGKILL。

**SIGKILL（9）**是强制终止：**不可捕获、不可忽略**，内核立即终止进程，
不给清理机会。SIGKILL 杀不掉的进程只有一种：处于不可中断睡眠（D 状态，
通常在等磁盘 I/O）时，信号要等 I/O 完成才投递。

发信号的命令是 `kill`，名字虽叫 kill，实际是“发信号”：`kill -TERM <pid>`
发 SIGTERM，`kill -9 <pid>` 发 SIGKILL，`kill -l` 列信号表。默认不带
信号编号的 `kill <pid>` 发的是 SIGTERM。

## 僵尸进程与孤儿进程

**僵尸进程（zombie）**：子进程退出后，父进程没有调用 `wait()` 回收，
子进程的进程表项残留，状态为 Z，只占一个表项、不占内存。僵尸进程
本身无害，堆积过多会耗尽 PID 数量。根治办法是父进程正确 `wait()`，
或让父进程忽略 `SIGCHLD`（内核自动回收）。

**孤儿进程（orphan）**：父进程先于子进程退出，子进程成为孤儿，立即
被 PID 1（`init` / systemd）收养，由 PID 1 负责在它退出时 `wait()` 回收。
孤儿进程继续正常运行，`nohup` 配合 `&` 后台运行的任务就是靠这个机制
在 shell 退出后继续活着。

## nice 值与优先级

`nice` 值范围是 **-20 到 19**，值越小优先级越高（越“不 nice”）。
普通用户只能把自己进程的 nice 值调大（降低优先级），调小（提高优先
级）需要 root 或 `CAP_SYS_NICE` 能力。

```bash
# 以 nice 值 10 启动（比默认 0 更低优先级）
nice -n 10 ./worker

# 已运行进程改 nice 值（只能调大，除非 root）
renice -n 10 -p <pid>
```

nice 值影响的是 CPU 时间分配权重，不是硬性的执行顺序：高优先级进程
在 CPU 争用时分到更多时间片，CPU 空闲时低优先级进程一样全速跑。

## OOM killer：内存耗尽时的最后手段

系统内存耗尽时，内核的 OOM killer 按 `oom_score` 评分选一个进程杀掉，
保住系统不死机。评分综合占用内存大小、运行时间、是否为 root 进程等
因素：占用内存多、运行时间短的进程分数高，优先被杀。

`/proc/<pid>/oom_score` 可读当前评分，`/proc/<pid>/oom_score_adj` 可调
整（-1000 到 1000，-1000 表示永不杀）。RagMate 的 `db` 服务在
Compose 里配了 `oom_score_adj: -500`，内存紧张时优先杀应用进程、不杀
数据库。不要把关键服务设成 -1000：内存耗尽时内核杀无可杀，整个系统
可能直接挂起。
